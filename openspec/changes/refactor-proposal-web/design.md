# Design

## Context

參見 `proposal.md`。當前系統面臨智慧電表時序分析與自然語言推理斷層、時間電價劇烈變動及大模型決策缺乏物理安全防護之問題。本設計旨在建立一套解耦、可解釋且受白名單工具約束的電力領域專用 AI Agent 系統。

## Goals / Non-Goals

**Goals:**
- 實現八大模組之分層架構設計，將感知輸入、推理規劃、資料檢索、數值計算、領域物理模型、安全決策與交互輸出明確切分。
- 建立嚴格的白名單工具調用機制，禁止大模型直接執行未審查之系統或硬體控制指令。
- 實作信心度閥值機制（Threshold = 0.80），低於閾值時主動發起對話澄清而非瞎猜。
- 實作雙重過載安全守門（預測尖峰功率超標 90% 觸發主動降載，即時遙測超標 98% 觸發緊急斷路保護）。
- 建立純靜態、零後端相依之單頁應用（SPA）展示網站，可直接託管於 GitHub Pages。

**Non-Goals:**
- 不涉及直接對真實硬體斷路器（Physical Circuit Breakers）發送強電操作指令（本階段僅發送模擬 BACnet/MQTT 控制封包與虛擬告警）。
- 不在提案階段捏造或虛構固定的準確率或節電百分比實測數據。

## Decisions

### 決策 1：採用 ReAct (Reasoning + Acting) 結合白名單工具分派
- **選擇方案**：Agent 採用 ReAct 框架進行思維鏈推理，所有外部運算（NILM、時序預測、舒適度評估、安全斷路）均透過受限白名單 Function Calling 執行。
- **替代方案考慮**：
  - *端到端端大模型直接生成排程*：容易產生嚴重的數值幻覺，且無法保證滿足電氣物理與契約容量約束。
  - *純傳統規則引擎 (Rule-based)*：缺乏自然語言互動彈性與複雜空間多模態情境泛化能力。

### 決策 2：雙重門檻安全防護機制 (Safety Guard & Circuit Breaker)
- **選擇方案**：在決策引擎輸出至互動模組間設置獨立安全守門閥，以物理契約容量公式為硬指標（90% 降級，98% 斷路）。
- **替代方案考慮**：
  - *讓 LLM 在 Prompt 中自我約束*：實測顯示 LLM 在長對話中存在指令漂移與安全遺忘風險，無法作為安全認證憑據。

### 決策 3：前端採用 Tailwind CSS + Mermaid.js + Chart.js 純靜態整合架構
- **選擇方案**：全客戶端動態渲染架構，透過 CDN 引入，零編譯、零後端伺服器依賴，完美相容 GitHub Pages。
- **替代方案考慮**：
  - *Next.js / Node.js 伺服器渲染*：部署複雜度高，難以作為免維護的靜態提案展示成果。

## Risks / Trade-offs

- **[NILM 分解精度受低採樣率影響]** → 針對 15 分鐘 AMI 遙測資料，結合機率狀態轉移模型與用戶主動澄清迴圈（Confidence < 0.80）以補足高頻特徵缺失。
- **[空調降載影響用戶舒適度]** → 導入 2R2C 建築熱阻抗模型與 PMV/PPD 硬約束，確保室內溫度升幅在人體舒適安全區間內。
- **[尖峰電價動態變動風險]** → 定期由檢索模組同步台電最新 API，本地快取離線費率表作為容災備援。
